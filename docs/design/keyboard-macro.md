# キーボードマクロ

記録するのはキー入力そのものではなく、それが意味する操作（`MacroStep`）です。文字入力とカーソル移動・削除は View が `TextArea` の入力から翻訳し、`EditorCommandCatalog` のコマンドは `RunEditorCommandAsync` の分岐 1 箇所で記録します。再生は入力を流し直さず、`DocumentViewModel` へ同じ操作を当て直します。

`MacroStore.Load` は空名を除外して20件へ制限した後、手順と挿入文字列を検証します。null配列・要素や必要な値の欠落は空ライブラリへ戻し、パレットと通常編集を利用可能に保ちます。

入力を溜めて再送する作りにしないのは、IME・フォーカス・タイミングに依存して不安定になり、ヘッドレスのテストで固定できず、保存もできないためです。代わりにマウスでのカーソル移動とクリップボードは記録できません。

1 回の実行は `UndoStack` のひとつの塊にまとめます。100 回流したマクロを `Ctrl+Z` 100 回で戻すことになると、取り消せないのと変わらないためです。再生中は記録を止めます（記録中に実行できてしまうと、マクロが自分自身を書き足して際限なく伸びます）。入力ダイアログを開くコマンド（`GoToLine`、`BookmarkPattern`、CSVソート）は再生時に止まるので、再生側で読み飛ばすのではなく記録の時点で弾き（`NotRecordable`）、一覧に「動かない手」を残しません。

検索の手は AvaloniaEdit の `SearchPanel` を参照せず、記録した時点の条件（文字列・大文字小文字・正規表現）を手自身が持ち回り、再生では `DocumentViewModel.FindNext` がモデル側で探します。View の状態に依存させるとモデル層だけで再生できなくなるためです。
