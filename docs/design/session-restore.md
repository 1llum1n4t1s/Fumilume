# セッションの復元

復元は通常のオープン・保存と同じ排他区間で行い、同じ絶対パスのタブは再利用します。旧セッションに同じパスの未保存本文が複数残っている場合は、2枚目以降の保存先を外して文書として復元し、競合する上書きを防ぎます。

終了時のワークスペースは `MainWindowViewModel` がタブ順・選択・ピン状態を `SessionState` へ写し、`SessionStateService` が `session.json` と、未保存の本文だけを持つ控えファイルへ分けて書きます。通常終了は初回復元の完了を待ちます。待機できないOS終了では、復元中に編集した現在のタブへ、未処理の前回タブと復元に失敗した未保存タブを足して同期保存します。本文を設定と同居させないのは、数MBの本文が混ざると保存コストと破損時の被害が広がるためです。控えは保存のたびに新しい名前で書き、一覧を確定させたあとにだけ古い控えを消します。同じ名前へ上書きすると、一覧の書き込み失敗時に書きかけが別タブの内容へすり替わるためです。

復元では、未保存の変更があるタブは控えた本文を正本にしてディスクを読まず、変更が無いタブはディスクを読み直し、実体が消えたタブは復元しません。未保存の控えが実在しないときだけ、保存済みならディスクの内容で開いて失った旨を伝え、新規文書なら復元しません。控えが一時的に読めない、またはタブ構築中に例外が起きたときは、その未保存タブと控えへの参照を次のセッション一覧にも残します。ディスクから読み直す文書とPDFには、通常の「開く」と同じ大容量ファイル確認を適用します。

未保存バッファを控えるタブには、保存先の最終更新時刻（UTC Ticks）とサイズを任意項目 `DiskLastWriteUtcTicks`・`DiskLength`（`DiskStamp`）として添えます。内容は読まないため起動は遅くなりません。復元した未保存文書は保存基準を持たないので、最初の監視通知で基準を記録しますが、控えた状態が現在のディスクと食い違うときは黙って置き換えず、通常の外部変更確認（「ディスクの内容を読み込む」か「復元した編集を維持する」）へ進めます。維持を選ぶと現在のディスク内容を基準にし、保存による上書きを明示の承認として扱います。食い違わない、または項目が無い旧セッション・読めないファイル・不正値では基準を記録するだけです。照合前に再度保存するときは控えた状態を引き継ぎます。

終了時は `PersistSessionStateAsync` が復元完了を待ってから書き直します。復元途中で書くと、未復元タブの控えを未使用と判断して消すためです。復元が始まる前の保存要求では前回セッションを正本として触りません。存在する `session.json` を読めなかった場合も、空セッションと区別し、既存の一覧と控えを上書きしません。その起動中の新しい編集は `session-recovery` ディレクトリへ、一覧と本文をまとめたコミット済みスナップショットとして控えます。次回は主一覧が読める場合も回復スナップショットを合流し、全スナップショットと本文を読めた場合だけ通常セッションへ昇格して回復領域を消します。1件でも読めなければ合流と清掃を延期し、主一覧も読めなければ新しい編集を別スナップショットへ追記します。通常のウィンドウ終了とアプリ終了（macOS の ⌘Q を含む）では、`RestoreSession` が有効な間は未保存の確認を出さない代わりに、控えへ書けなかったときは未保存文書がある限り終了を中止します。OS終了ではダイアログと非同期待機を挟まず、確定しているタブ状態を同期的に控えます。無効なときは主一覧・回復一覧と両方の控えを削除して従来の確認へ戻します。

アプリは `SingleInstanceCoordinator` がユーザーデータ置き場の排他リースを保持し、同じユーザーによる後続起動の引数を名前付きパイプで最初のプロセスへ渡します。相対パスは送信側プロセスの作業フォルダーで絶対化します。転送されたファイルは初回セッション復元の完了後に開くため、ファイル関連付けから何度起動しても、複数プロセスが同じ `session.json` と未保存バッファを競合更新しません。転送できなかった場合は無言で終了せず、再実行が必要なことを利用者へ通知します。
