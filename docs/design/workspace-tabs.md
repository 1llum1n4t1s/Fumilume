# タブと状態モデル

`MainWindowViewModel.Tabs` は `WorkspaceTabViewModel` の集合で、次の4種類を扱います。設定以外はピン留めでき、ピン留め群、通常群、設定の順を保ちます。

- `DocumentViewModel`: 編集可能なテキスト文書。未保存状態、パス、文字コード、改行、カーソル、Markdownプレビュー状態を保持する。
- `PdfDocumentViewModel`: 読み取り専用PDF。ページと表示画像を保持し、編集・保存コマンドの対象外になる。
- `GrepResultTabViewModel`: フォルダ横断検索の結果。検索条件と一致行を保持し、選んだ行から該当ファイルを開く。
- `SettingsTabViewModel`: 単一の設定画面。重複して開かず、常に文書・PDFタブの後ろへ置く。

選択タブの型から、エディタ、Markdownプレビュー、PDFビュー、検索結果、設定ビューの表示とコマンド可否を導出します。表示可能な文書・PDF・検索結果が0件になった場合は空の文書を作り、設定タブだけの状態を残しません。

## タブを閉じる

閉じる処理は2つに分けます。`CloseTabCoreAsync(tab, recordClosed)` は未保存文書の保存・破棄・取消の確認を出し、確認が通ると `RemoveTabCore(tab)` を呼びます。`RemoveTabCore` は確認を出さず、選択の移動、空文書の補充、PDF・検索結果の破棄だけを行い、`_openPathsGate` の内側から呼べます。閉じた履歴には残しません。一時タブの差し替えと、ファイル操作に伴う閉じは `RemoveTabCore` か `recordClosed=false` を使います。

## 閉じた履歴

利用者が閉じたパス付きの文書・PDFだけを `MainWindowViewModel` のメモリへ新しい順に記録します（上限25件、メニュー表示は10件、同じパスは古い方を消す）。セッションには保存しません。記録しない経路は、一時タブの差し替え、空文書の除去、削除・改名に伴う閉じです。「閉じたタブを開く」（`Ctrl+Shift+T`、macOSは `⇧⌘T`）と「最近閉じたタブ」で開き直した項目は履歴から外し、ファイルの改名・移動では履歴のパスも新しいパスへ付け替えます。

## タブ操作の規則

- ピン留め群と通常群は別の群として扱い、移動・並べ替え・一括ピン留めで群の順序（ピン留め群、通常群、設定タブ）を崩さない。設定タブは常に末尾に残す。
- 「すべてのピン留めを解除」は後ろから解除して、元の並び順を保つ。
- 先頭へ・末尾へ移動は同じ群の中だけで動かす。名前順・パス順・並び順の反転は群ごとに別々に行う。
- 下側・上側・他のタブを閉じる操作はピン留めを残す（他のタブを閉じるでは設定タブも閉じる対象）。複数のタブは順に閉じ、未保存の確認で取消が選ばれたら残りも閉じずに止める。複数閉じの途中ではゲートを保持しない。
- 開き直す操作の対象はパス付きのテキスト文書だけで、PDFは対象外にする。
- 「新しいタブを下に開く」は、新しい文書をピン留め群の後ろ・設定タブの前に挿入する。

## ファイル操作とタブの整合

改名・移動・削除は `MainWindowViewModel.FileOperations.cs` が `_openPathsGate` を保持したまま行います。影響するPDFを閉じて位置・ズーム・ピン留め・選択を控え、シェル操作の後、実際に済んだ組（`Completed`）ごとに、同じパスまたは配下の文書へ `DocumentViewModel.Relocate(newPath)` を適用します。`Relocate` は `FilePath` だけを変え、未保存状態・保存基準・取り消し履歴を保ちます。続けてカーソル位置と閉じた履歴を付け替えて設定を1回保存し、PDFを新しいパス（失敗時は元のパス）で開き直して控えを戻し、ゲートを解放してからツリーを更新します。削除後は未編集の文書を `RemoveTabCore` で閉じ、未保存の文書は「ディスクに無い」状態でタブに残します。移動先が自分自身・配下の場合と、移動先に同名の開いているタブがある場合は、事前に断ります。コピーの貼り付けではタブ・カーソル位置・閉じた履歴を付け替えず、ツリーだけを更新します。保存はゲートを取得した後に `FilePath` を読み直して書き込み先を決めるので、シェル操作の最中に始めた保存も新しいパスにだけ書きます。PDFの開き直しでは大容量ファイルの確認を出しません。

## 起動

1. `Program` が `AppLogger` を初期化し、未処理例外を記録する。
2. Velopackがインストール・更新後の関連付け更新と、アンインストール前の関連付け解除を処理する。
3. `App` が `SettingsService` から設定を1回読み、初回描画前に `ThemeService` へ適用する。
4. `MainWindow` と `MainWindowViewModel` が作られ、セッション復元後に起動引数のファイルを開く。後続プロセスからの転送も同じ順序を保つ（[セッションの復元](session-restore.md)）。

検証は `global.json` で Microsoft.Testing.Platform を選択し、xUnitの実行可能プロジェクトを `dotnet test` から実行します。VSTest向けのTest SDK・アダプターには依存しません。
