# 機能の入口

操作の入口は 3 層に分けます。常時出すツールバーは「新規」「開く」「保存」「元に戻す」「やり直す」「検索」「設定」と、文脈で出る Markdown / CSV プレビューだけにし、`EditorCommandCatalog` の編集コマンドは編集画面の右クリックメニュー（区分ごとのサブメニュー）から辿ります。すべての機能はコマンドパレット（`Ctrl+Shift+P`）に `CommandPaletteEntry` として並び、ファイルを開く・保存といったワークスペース操作も同じ一覧へ載せて、今の状態で実行できるものだけを出します。

タブ一覧とフォルダツリーの右クリックメニューは、XAMLではなくC#で `MenuFlyout` を組み立てます。`MainWindowViewModel.ContextMenus.cs` が `ContextMenuEntry`（見出し・実行・ショートカット表示・有効状態・子項目・ツールチップ、区切り）の一覧を返し、`MainWindow.ContextMenus.cs` が `ContextRequested` を1か所で受けて、ファイルのクリップボード有無を確かめてから `MenuFlyout` へ変換します。ショートカット表示は Windows 表記で持ち、macOSでは View が ⌘ 表記へ変える。有効状態の判定は ViewModel の `Can…` に置き、メニューとコマンドパレットで同じ判定を使います。

「閉じたタブを開く」は `Ctrl+Shift+T`（macOSは `⇧⌘T`）に割り当てます。コマンドパレットには、メニューと同じ操作として「閉じたタブを開く」「他のタブを閉じる」「下側のタブを閉じる」「パスのコピー」「エクスプローラーで表示」（macOSは Finder）を選択タブ向けに追加します。

機能を足すたびにツールバーへ並べると横に伸びて優先度が消え、同じ機能へ最大 4 つの入口ができていたため、増える先をパレットとメニューに固定しています。
