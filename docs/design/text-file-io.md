# テキストの読込・編集・保存

1. `MainWindowViewModel` がダイアログ・起動引数・ファイルのドロップから受け取ったパスを絶対化し、開く要求を直列に処理する。大文字・小文字を区別せず同じパスのタブがあれば、再読込せずそのタブを選ぶ。
2. `DocumentFileService` がUTF-8／16／32のBOM、BOMなしUnicodeのNUL配置、厳密なUTF-8、ISO-2022-JPの識別シーケンス、EUC-JP、Shift_JISの順に文字コードを決め、最初に現れる改行形式を記録する。追記中の末尾がマルチバイト文字の途中なら、内容が変化した場合に限って短時間後に1回再判定する。利用者がステータスバーから選び直した場合は、その値を保存メタデータへ反映する。
3. `TextDocumentContent` を `DocumentViewModel` へ読み込み、AvaloniaEditの文書を編集元データとする。
4. 保存時は文書が保持する文字コードと改行へ正規化し、同じディレクトリの一時ファイルから置き換える。設定が有効な場合だけ置換前の内容を `.bak` に残す。保存先の確定と手動の開き直しはオープン・復元・外部変更反映と同じ排他区間で行い、別タブが使っているパスへの保存は書込み前に拒否する。文字コード・改行は本文のUndoとは独立して未保存状態へ反映する。
5. `ExternalFileChangeMonitor` が開いている文書のディレクトリを監視し、変更・作成・削除・名前変更を同一パスごとにまとめる。ウィンドウが再び有効になったときは記録したファイル状態も照合し、取りこぼしを補う。未編集の文書は自動で読み直し、未保存編集がある場合は破棄前に確認する。アプリ自身の保存通知は保存時の内容と照合して無視する。外部から削除された文書は本文とパスを保持して未保存扱いにする。一時的に読めない場合は再試行を続けるが、成功するまで同じエラーダイアログを繰り返さない。
6. 保存・クローズ時に、設定が有効ならファイルごとのカーソル位置を記録する。

保存開始時に本文・文字コード・改行と文書の版を取得し、書込みに成功したスナップショットだけを保存基準にします。待機中の追加入力は未保存のまま残し、Undoで保存した本文へ戻った時点でUndo履歴の保存位置を再設定します。ディスクとの比較には改行正規化後の本文、Undoの保存位置の判定には正規化前の編集本文を使い、混在改行でも保存待ちの編集を失いません。

読込は `FileShare.ReadWrite | FileShare.Delete` で開き、書き込み中のログの読取と追記・ローテーションを許容します。ストリームを開いた直後の長さまでを読み、途中で切り詰められた場合は実際に読めたバイトだけをデコードします。相手が読み取り共有を許可していないファイルは読込エラーです。テキストは1個のbyte配列へ読むため `Array.MaxLength` を上限とし、超えるファイルは読込前に理由を示して拒否します。PDFは対象外です。

書式整形は `DocumentFormattingService` が形式ごとに処理します。JSONとXML/XAML系は構文解析、C#・JavaScript・TypeScript・CSSは文字列とコメントを除外した括弧構造から字下げを決めます。未対応形式と不正構文は文書を変更せず、成功時は全体置換を1回のUndo操作にします。

IME の未確定文字は `EditorInputMethod` が AvaloniaEdit の入力クライアントを包み、TextView 上の表示専用レイヤーへ描きます。未確定文字は文書・Undo・セッション・マクロへ書かず、確定時だけ既存の TextInput 経路へ流します。取消、フォーカス移動、文書切替では表示を消します。
